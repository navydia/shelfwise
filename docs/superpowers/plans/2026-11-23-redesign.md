# Shelfwise Redesign Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rebuild Shelfwise's front end in the approved Shelf Tag / Fig brand, and change the data model to a single "on the list" flag with categories, aisles, price sources, store colours and a Finish shopping step.

**Architecture:** The server gains a versioned SQLite migration and a few routes. The front end stays vanilla ES modules with no build step. Pure logic (filtering, grouping, trips, budget tag, money) moves into `public/lib/*.js` so vitest can test it directly. DOM code lives in `public/views/*` and shared widgets in `public/ui/*`. Styling is CSS custom properties in `public/tokens.css` plus `public/app.css`.

**Tech Stack:** Node 22.16+ (`node:sqlite`), Express 5, TypeScript via tsx, vitest + supertest, vanilla JS/CSS PWA, self-hosted fonts from `@fontsource` packages.

**Spec:** `docs/superpowers/specs/2026-11-23-redesign-design.md` (mockups in `docs/superpowers/specs/2026-11-23-redesign-mockups/`, file 1 is the latest). Read the spec before any task; it holds every colour, size and copy string this plan refers to by name.

## Global Constraints

- Node `>=22.16`; no new runtime dependencies on the server. Font packages are dev-only and their `.woff2` files are copied into `public/fonts/` and committed.
- Writes are never queued offline. Only ticks live on the phone (`localStorage` through `api.store`).
- Light mode only. Every text colour must meet 4.5:1 and every control or icon 3:1. Use only the spec's tokens; no new colours.
- Fonts: Figtree 800 (page titles), Bricolage Grotesque 700/800 (wordmark, prices, labels, buttons), IBM Plex Mono 400 (raw receipt lines), and the system font for body text. Nothing is loaded from Google at runtime.
- Store colours are exactly `fig #4A3242, claret #5A2E36, cinnamon #553423, olive #40402A, forest #2D4334, teal #22434A, harbor #2E3A55, slate #3A3D45`, with `fig` as the default.
- The seed categories are exactly: Produce, Dairy & eggs, Meat & fish, Bakery, Pasta & grains, Oils & condiments, Canned & jarred, Baking, Snacks, Frozen, Drinks, Household.
- Viewport target: iPhone, 390×844 CSS px, with safe areas respected (`env(safe-area-inset-*)`).
- Commit on the `redesign` branch with `git -c user.name="Claude" -c user.email="noreply@anthropic.com" commit`, ending each message with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Git has no identity configured on this machine; do not change the git config.
- Run tests with `npm.cmd test` on Windows PowerShell, or `npm test` in bash. The suite must be green at every commit.

## Review Focus

1. **Upgrading her real database:** an existing `shelfwise.db` with Low and Out items, receipts and photos. After upgrade, every Low or Out item is on the list, nothing else changes, and opening it a second time changes nothing. *Test: Task 1, `migrates_old_database_once`.*
2. **Long names:** a 40+ character staple name or store name. Rows, banners and the store pill truncate with an ellipsis; buttons are never pushed off-screen. *Check: Task 10, browser step.*
3. **Finish shopping with no signal:** the request fails, the ticks and the trip start stay exactly as they were, and she sees "You're offline. Nothing was changed." *Test: Task 12, browser step with the server stopped.*
4. **A ticked staple that moves store or is deleted:** its tick must leave the old store's trip, so Finish never sends an item from another store and the server never rejects the whole batch. *Test: Task 6, `remove_drops_ids_from_every_trip`; Task 4, `finish_rejects_items_from_other_store`.*
5. **Typed money values** (price and budget): `4`, `4.5`, `$4.50` are accepted. Blank means "no price" or "no budget". `abc`, `-3` and `4.555` are rejected with a message and nothing saved. *Test: Task 6, `parseDollars_matches_server`.*

### Task 7: Client logic: pantry view and list grouping

**Files:**
- Create: `public/lib/list-groups.js`, `public/lib/pantry-view.js`
- Test: `tests/client-groups.test.ts`, `tests/client-pantry.test.ts`

**Interfaces:**
- `list-groups.js`:
  - `compareAisles(a: string|null, b: string|null): number`. Purely numeric labels come first, sorted by number; then text labels alphabetically (case-insensitive); `null` comes last.
  - `groupList(lines, by: 'aisle'|'category'|'none', categories: {id,name}[], ticked: Set<number>, tickedToBottom: boolean): { key: string, title: string|null, items: ListLine[] }[]`
    - Titles are `'Aisle 4'`, `'No aisle'`, the category name, `'No category'`, or `null` for `none`.
    - Items within a group are sorted by name.
    - When `tickedToBottom` is set, ticked items leave their groups for a final `{ key: 'cart', title: 'In the cart' }`, and empty groups are dropped.
- `pantry-view.js`: `pantryView(items, opts, ctx)`, where:
  - `opts = { query: string, show: 'all'|'onList', categoryId: number|null, noPhoto: boolean, sort: 'store'|'aisle'|'name'|'category'|'recent' }`
  - `ctx = { stores: {id,name,color}[], categories: {id,name}[], storeId: number|null }`, where `storeId: null` means All stores.
  - It returns `{ mode: 'stores'|'groups'|'flat', sections: { key, title: string|null, color?: string, items }[], shown: number, total: number, activeFilters: number }`.
  - The rules:
    - Filter by store, `show`, `categoryId`, `noPhoto`, and a case-insensitive substring `query` on the name.
    - A non-empty `query` always gives `flat`, sorted by name.
    - `sort: 'store'` gives `stores` sections in the order of `ctx.stores` (main first, as the API sends them), with colour and items by name.
    - `aisle` and `category` give `groups` with the same titles as `groupList`.
    - `name` and `recent` (by `changedAt`, newest first) give `flat`.
    - `activeFilters` counts `show !== 'all'`, `categoryId !== null` and `noPhoto`.
    - When `ctx.storeId` is set and `sort === 'store'`, treat it as `'aisle'`. The sheet hides Store in that case; this makes stale saved settings safe.
